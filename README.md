# 학술제 심사 평가 웹앱

심사위원은 휴대폰이나 노트북에서 링크를 열어 발표자를 A~E 등급으로 평가하고, 관리자는 부문별 순위를 바로 확인하는 웹앱입니다.

- **심사위원 화면** `index.html`: 이름 입력 → 구두발표/포스터발표 선택 → 평가 → 제출
- **관리자 화면** `admin.html`: 비밀번호 입력 → 부문별 순위, 심사위원별 점수, 심사의견, 제출 현황, 엑셀(CSV) 내려받기, 인쇄
- **결과 저장**: 구글 시트 (Apps Script)
- **호스팅**: GitHub Pages

## 파일 구성

| 파일 | 내용 |
|---|---|
| `config.js` | **설정 파일**: 행사명, 구글 시트 연결 주소, 등급별 점수표, 평가항목, 부문별 발표자 명단과 발표주제 |
| `index.html` | 심사위원용 평가 화면 |
| `admin.html` | 관리자용 결과·순위 화면 |
| `assets/` | 화면 동작 코드와 디자인 (보통은 고칠 일이 없습니다) |
| `apps-script/Code.gs` | 구글 시트에 붙여 넣을 결과 수집 코드 |

## 1. 설정 바꾸기 (`config.js`)

메모장이나 VS Code로 `config.js`를 열어 고칩니다. GitHub 웹사이트에서 파일을 열고 연필 아이콘으로 바로 고쳐도 됩니다.

- **발표자 추가**: 해당 부문의 `presenters` 목록에 한 줄을 추가합니다.
  ```js
  { name: "홍길동", topic: "발표 주제" },
  ```
- **발표주제 수정**: `topic: "..."`의 따옴표 안을 고칩니다. 국문·영문 제목을 두 줄로 쓰려면 사이에 `\n`을 넣습니다.
- **지도교수·발표시간**: `advisor: "..."`, `time: "13:00 - 13:20"`. 포스터처럼 모두 같은 시간대면 부문에 `time`을 한 번만 적습니다. 첫 화면의 **발표 순서 · 시간 보기** 버튼이 이 값으로 시간순 목록을 보여줍니다.
- **등급별 점수**: 평가항목마다 `points: { A: 30, B: 27, ... }`에 적혀 있습니다. 구연·포스터 심사 기준과 배점표 그대로 넣어 두었습니다(A 100% · B 90% · C 80% · D 70% · E 60%).
- **부문·평가항목 이름**: `label: "..."`을 고칩니다.
- **첫 화면 문구**: `hero`에서 소속(`org`, `orgEn`), 슬로건(`tagline`), 큰 글씨(`display` = DTM, `displaySub` = ACADEMIC FESTIVAL)를 바꿉니다. 비워 두면 그 줄은 표시되지 않습니다.

> ⚠️ 심사가 시작된 뒤에는 **발표자 이름**과 **평가항목 순서**를 바꾸지 마세요. 제출된 결과를 이름과 항목 순서로 맞춰서 계산합니다.
> 발표주제·부문 이름·점수표는 언제 바꿔도 됩니다. 시트에는 등급(A~E)만 저장되므로, 점수표를 바꾸면 이미 제출된 결과도 관리자 화면에서 새 점수표로 다시 계산됩니다.

## 2. 구글 시트 연결 (처음 한 번)

> **현재 연결 상태 (2026-10-15)**
> - 결과 시트: BAT Lab 구글 드라이브의 `제3회 학술제 심사결과`
> - Apps Script 프로젝트: `학술제 심사 결과 수집` (script.google.com에서 독립 프로젝트로 만들고, 코드의 `SPREADSHEET_ID`에 위 시트 ID를 넣음)
> - 관리자 비밀번호: 프로젝트 설정 → 스크립트 속성 `ADMIN_PASSWORD`
>
> 아래는 처음부터 새로 연결할 때의 순서입니다. 시트에서 [확장 프로그램 → Apps Script]로 만들면 `SPREADSHEET_ID`는 비워 두면 됩니다.

1. [Google 스프레드시트](https://sheets.google.com)에서 빈 시트를 새로 만듭니다. (예: `제3회 학술제 심사결과`)
2. 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. 편집기에 있는 `Code.gs` 내용을 모두 지우고, 이 폴더의 `apps-script/Code.gs` 내용을 붙여 넣은 뒤 저장(💾)합니다.
4. **관리자 비밀번호 등록**: 왼쪽 **⚙ 프로젝트 설정** → 맨 아래 **스크립트 속성** → **스크립트 속성 추가**
   - 속성: `ADMIN_PASSWORD`
   - 값: 관리자 화면에서 쓸 비밀번호
   - **스크립트 속성 저장**을 누릅니다.
5. 오른쪽 위 **배포 → 새 배포** → 유형 선택(⚙)에서 **웹 앱**을 고릅니다.
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
   - **배포**를 누릅니다.
6. 권한 승인 창이 뜨면 본인 구글 계정을 고르고 허용합니다.
   "Google에서 확인하지 않은 앱" 경고가 나오면 **고급 → (프로젝트 이름)(으)로 이동**을 눌러 진행합니다. 본인이 만든 스크립트라서 나오는 경고입니다.
7. 배포가 끝나면 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 복사해서 `config.js`의 `appsScriptUrl`에 붙여 넣습니다.
   ```js
   appsScriptUrl: "https://script.google.com/macros/s/AKfycb.../exec",
   ```

첫 제출이 들어오면 시트에 탭이 자동으로 생깁니다.

- `구두발표` / `포스터발표`: 심사위원 × 발표자마다 한 줄 (현재 유효한 최신 제출)
- `제출기록`: 모든 제출 원본 (다시 제출해서 덮어쓴 내용도 여기에 남습니다)

> - `Code.gs`를 고친 뒤에는 **배포 → 배포 관리 → ✏️ → 버전: 새 버전 → 배포**를 해야 반영됩니다. 이렇게 하면 URL은 그대로입니다. "새 배포"를 다시 하면 URL이 바뀝니다.
> - 학교·기관(Google Workspace) 계정은 "모든 사용자" 옵션이 막혀 있을 수 있습니다. 그럴 때는 개인 Gmail 계정으로 시트를 만드세요.

## 3. GitHub Pages로 올리기

1. GitHub에서 새 저장소(repository)를 만듭니다. 무료 계정이면 **Public**이어야 Pages를 쓸 수 있습니다.
2. **Add file → Upload files**로 이 폴더의 파일을 모두 올립니다 (`index.html`, `admin.html`, `config.js`, `assets` 폴더 등). `.claude` 폴더는 올리지 않아도 됩니다.
3. 저장소의 **Settings → Pages** → Source: **Deploy from a branch** → Branch: `main`, 폴더 `/ (root)` → **Save**
4. 1~2분 뒤 주소가 생깁니다.
   - 심사위원용: `https://<아이디>.github.io/<저장소이름>/`
   - 관리자용: `https://<아이디>.github.io/<저장소이름>/admin.html`

심사위원용 주소는 QR 코드로 만들어 행사장에 붙여 두면 편합니다. 관리자용 주소는 공유하지 마세요. 비밀번호가 없으면 결과는 보이지 않습니다.

> GitHub에서 `config.js`를 고치면 1~10분 안에 사이트에 반영됩니다(GitHub Pages 캐시). 심사위원에게는 페이지를 새로고침하도록 안내하세요.

## 4. 행사 당일

**심사위원**
1. 링크를 열고 이름을 입력한 뒤 **구두발표** 또는 **포스터발표**를 고릅니다.
2. 발표자마다 항목별로 A~E를 고릅니다. 필요하면 심사의견(포스터는 비고)을 씁니다.
3. 불참이나 이해관계 등으로 평가하지 않을 발표자는 **평가 안 함**을 누릅니다.
4. **제출하기**를 누릅니다. 손대지 않은 발표자가 있으면 제출할 때 "평가 안 함"으로 처리할지 묻습니다.

- 입력 내용은 그 기기에 **자동 임시저장**됩니다. 창을 닫아도 같은 기기에서 같은 이름으로 들어오면 이어서 할 수 있습니다.
- 같은 이름으로 **다시 제출하면 이전 제출을 덮어씁니다.** 제출 후 수정할 때 쓰면 됩니다.
- 이름은 매번 똑같이 입력해야 합니다. 앞뒤 공백은 무시하지만, 글자나 중간 띄어쓰기가 다르면(예: `이교수`와 `이 교수`) 다른 심사위원으로 집계됩니다.

**관리자**
- `admin.html`에서 비밀번호를 입력하면 부문별 순위가 나옵니다. **새로고침**을 누르면 최신 제출이 반영됩니다.
- **제출 현황** 탭에서 누가 언제 제출했는지, 이름 오타가 있는지 확인할 수 있습니다.
- **엑셀(CSV) 내려받기**는 부문별 순위와 심사위원별 점수·등급을 파일로 저장합니다. **인쇄**는 모든 부문의 순위표를 한 번에 출력합니다.

## 5. 점수 계산 방식

1. 각 항목의 등급(A~E)을 `config.js`의 `points`(심사 기준과 배점표)에 따라 점수로 바꿉니다. 예) 포스터 '내용' B = 40.5점
2. 심사위원별로 항목 점수를 더해 총점(100점 만점)을 구합니다.
3. 발표자별로 **평가한 심사위원들의 총점 평균**을 구합니다. "평가 안 함"은 평균에서 빠집니다.
4. 부문 안에서 평균 총점이 높은 순서대로 순위를 매깁니다. 평균이 같으면 같은 순위로 표시합니다(예: 1, 2, 2, 4).

관리자 화면의 "합계"는 참고용입니다. 평가한 심사위원 수가 발표자마다 다르면 합계로는 비교할 수 없습니다.

## 6. 미리 테스트하기 (테스트 모드)

`config.js`의 `appsScriptUrl`이 비어 있거나, 내 컴퓨터(`localhost`)에서 열면 **테스트 모드**로 동작합니다. 그래서 내 컴퓨터에서 디자인을 미리 볼 때는 실제 구글 시트에 아무것도 기록되지 않습니다. 화면 위에 노란 안내가 뜨고, 제출 결과는 그 브라우저에만 저장됩니다. 같은 브라우저에서 `admin.html`을 열면 비밀번호 없이 결과를 볼 수 있고, **테스트 결과 지우기**로 지울 수 있습니다.

내 컴퓨터에서 열어 보려면 이 폴더에서 아래 명령을 실행하고 브라우저로 `http://localhost:8000`에 접속합니다. 파이썬이 필요합니다.

```bash
python -m http.server 8000
```

## 7. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| "서버에 연결하지 못했습니다" | `appsScriptUrl`이 `/exec`로 끝나는지, 배포의 액세스 권한이 **모든 사용자**인지 확인하세요 |
| 관리자 화면에서 "ADMIN_PASSWORD를 먼저 등록해 주세요" | 2단계 4번(스크립트 속성)을 하세요 |
| `Code.gs`를 고쳤는데 그대로임 | 배포 관리에서 **새 버전**으로 다시 배포하세요 |
| 명단을 고쳤는데 화면이 그대로임 | GitHub Pages 반영까지 최대 10분 걸립니다. 기다린 뒤 새로고침하세요 |
| 심사위원 이름 오타로 두 명처럼 집계됨 | 구글 시트의 `구두발표`/`포스터발표` 탭에서 심사위원 칸을 직접 고치세요 |
